## X thread

**1/**
> Your agent reads a web page. Something hidden in it tells the agent to send $1,000 somewhere. It does.
>
> Whose fault was that?
>
> Right now there's genuinely no way to answer. Every incident gets argued from scratch and then forgotten.

**2/**
> So I want to build the boring version first. No payouts, no insurance, no bonds.
>
> Just a place where the question gets answered on the record.
>
> Someone files a case. Evidence goes in. Validators investigate. A verdict comes out.

**3/**
> The verdict is one of four:
>
> the developer
> the user
> the agent itself
> or nobody, because the attack was good enough that no one would've caught it
>
> Plus the reasoning behind it. Public, permanent.

**4/**
> That third option is one I haven't seen anywhere.
>
> Developer built it right. User used it right. And the agent still made a bad call on its own.
>
> That's going to be a real category and nothing in how we currently think about liability has a slot for it.

**5/**
> Why this needs GenLayer and not a website:
>
> the developer and the user are on opposite sides of this. Neither should own the thing that decides it.
>
> And the attack is usually a public page, so validators can go read the real thing instead of trusting a screenshot.

**6/**
> The obvious question is where's the money. Insurance, payouts, all that.
>
> But you can't price a risk you can't attribute. Nobody knows what share of agent failures are actually negligence, because nobody has ever counted.
>
> This is the part that has to exist first.

**7/**
> A few hundred rulings in, you'd have something that doesn't exist today. An actual record of how agents fail and who was responsible when they did.
>
> Everything else gets built on that.
>
> @GenLayer #AgentTank

**Notes / Description** (~946 chars, limit is 1000)

> My pitch for Agent Tank — Injection Court.
>
> When an AI agent gets prompt injected and it costs someone money, there's no way to establish who was responsible. The developer blames the user, the user blames the developer, and it gets argued from scratch and forgotten.
>
> So this is deliberately the narrow version: no payouts, no insurance, no bonds. Someone files a case with the URL of the content that caused it and what the agent was running. Validators investigate and return one of four verdicts — developer, user, the agent itself, or unforeseeable — with reasoning. Public and permanent.
>
> It needs GenLayer because developer and user sit on opposite sides of the question, so neither should own the system answering it. And the attack is usually a public page validators can read themselves.
>
> Verdict-only is the point: you can't price a risk you can't attribute. Insurance and contracts come later. The record has to exist first.
>
> Full pitch on X, below.

## Why the thread is built this way

- Opens on a concrete incident rather than a thesis. Better first five seconds for a panel
  that has heard every agent pitch already.
- Post 4 carries the genuinely original idea (the "agent itself" fault category).
- Post 6 answers "where's the money?" before a panelist can raise it, and reframes the
  narrow scope as the reason the project is correct rather than a gap in it.
- Deliberately avoids: stacked triads, rhetorical-question-then-punchline, "here's the
  insight" signposting, and a zinger at the end of every post. Those read as machine-written.
